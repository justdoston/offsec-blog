Kerberoasting Attack & Theory

Theory behind Kerberoasting.

Before learning how to enumerate and attack, first we need to understand how kerberos authentication works.

Kerberos protocol helps us to authenticate other services in network without re-entering our password again. To do that is uses tickets.

Authentication Process

Name kerberos taken from mythological creature "cerberus" three headed dog who guards gates of hades, lord of the underworld.

Just like mythological concept, our kerberos protocol also has three heads.

  1. User
  2. Service
  3. KDC (Key Distribution Center)

KDC - is domain service who knows all credentials in Active Directory.

Let's focus this short explanation first before deep diving:

  1. You enter username and password to access domain joined computer
  2. KDC checks credentials, if it is true KDC gives you TGT (Ticket Granting Ticket) in other word it is your Passport
  3. If you want access to other service you use your TGT not your password anymore
  4. KDC then gives you Service Ticket (ST) a.k.a TGS
  5. Then you give TGS to service you wanted to access
  6. Service then allows you after getting TGS

Now let's focus each step one by one.

TGT

Employee enters his username and password to domain joined computer (windows ad) then KDC checks if it is true KDC allows access and gives TGT to that user.

TGT is user's identity card, it has all information of user such as name, date of account creation, security information, groups etc. There is an expiration date of TGT, mostly 10 hours by default.

TGT is encrypted by KDC's secret key which only KDC knows. Even the user himself can not change or read it. Along with TGT, KDC also provides a session key which is encrypted using the user's password.

TGS

Now, after receiving TGT, the user uses his TGT every time whenever he wants to access a service. User provides his TGT to KDC telling that he wants to access a service. KDC checks TGT expiration time, validation, etc. After that, KDC gives TGS to that user. Also known as Service Ticket (ST).

TGS is encrypted using the secret key of the service the user wanted to access. Therefore the user can not read the TGS he holds, and each TGS is unique. On the other hand, the service can read the TGS the user provides, because it is encrypted using the service's own secret key.

Misconfiguration which an attacker can take advantage of...

Now let's talk about the AS-REP Roasting attack. Remember the process where a user gets his TGT? User enters his username and password, and if correct, KDC gives TGT and a session key.

That process where a user proves he knows his credentials is called Pre-Authentication.

Sometimes administrators can disable Pre-Authentication. When disabled, a user gets his TGT without any prior authentication. As an attacker, we can just enumerate those users, and if some of them have disabled Pre-Authentication, we can just make a request for that user. What we actually need is the session key that comes with the TGT, because the session key is encrypted with the user's secret key derived from the password, so we try an offline hash cracking method to retrieve the user's password.

What an attacker needs: a user list, or 1 valid credential, to enumerate all Active Directory users.

Using user credentials to enumerate:

impacket-GetNPUsers inlanefreight.local/htb-student
